# ADR-001: Hermes Core owns workflow state

## Status

Accepted

## Context

Hermes Core is designed as a deterministic orchestration layer around AI capabilities.

Workers are ephemeral execution units. They do not own workflow state, scheduling decisions, permissions, or persistent memory.

The system must remain independent of any specific model provider or model implementation.

## Decision

Hermes Core owns:

- workflow state
- execution lifecycle
- scheduling
- artifact lineage
- policy enforcement
- capability selection

Workers receive execution packages from Hermes Core and return structured results.

Workers may recommend actions, but Hermes Core determines workflow transitions.

## Consequences

Positive:

- Models can be replaced without architectural changes.
- Workflows are reproducible.
- Execution can be audited.
- Human approval can be inserted at defined boundaries.

Negative:

- More infrastructure must exist outside the models.
- Worker interfaces require careful design.
